배포 가이드

고친 걸 어떻게 내보내지?

명령 두 줄이면 끝나요. 나머지는 GitHub이 합니다.

npm version patch       # 버전 올리기
git push --follow-tags  # 끝
먼저 알아둘 것

내 PC에 pet이 3마리 있어요

이걸 헷갈리면 "왜 안 바뀌지?" 가 시작돼요.

📦

핵심 — ①을 아무리 고치고 GitHub에 올려도 ③은 꿈쩍도 안 해요. ③을 바꾸려면 새 설치 파일을 구워서 Release에 올려야 합니다.
가장 헷갈리는 것

push 는 배포가 아니에요

둘은 아예 다른 일이에요.

📖

git push

레시피를 올리는 것
요리책 사이트에 글을 올림

앱과 아무 상관 없음

vs
🍜

Release

완성된 요리를 올리는 것
손님이 바로 받아먹을 수 있음

이게 업데이트 신호

설치된 앱은 레시피를 쳐다보지도 않아요. 완성품만 받아먹습니다. 그래서 코드만 push 하면 아무 일도 일어나지 않아요.
전체 그림

두 줄 치면 벌어지는 일

내가 하는 건 맨 위 하나뿐이에요.

내 PC
npm version patch 버전을 0.1.0 → 0.1.1 로 올리고, 커밋과 v0.1.1 태그를 자동으로 만들어요.
↓
내 PC
git push --follow-tags 코드와 태그를 GitHub에 올려요. 여기까지가 내 일의 전부.
↓
GitHub
"v 로 시작하는 태그가 올라왔네?" 약속해 둔 작업(.github/workflows/release.yml)이 저절로 깨어나요.
↓
GitHub
윈도우 컴퓨터를 빌려서 빌드  약 2분 내 PC에서 10분 걸리던 걸 남의 컴퓨터가 해줘요. 공개 저장소는 무료.
↓
GitHub
Release 만들고 파일 3개 올리기 설치 파일 · latest.yml · .blockmap
↓
설치본
6시간마다 확인 → 받아둠 → 다음에 켤 때 교체 다 받으면 말풍선에 "새 버전을 받아뒀어요" 라고 알려줘요.
업데이트의 정체

앱은 숫자 하나만 봐요

latest.yml 이라는 쪽지에 적힌 버전이 전부예요.

# latest.yml — GitHub에 올라가 있는 쪽지
version: 0.1.1
path: ClaudePet-Setup-0.1.1.exe
sha512: /Z8oauO1nRuELRv1...
0.1.0
내 앱이 알고 있는 버전
≠
0.1.1
쪽지에 적힌 버전

다르다  →  받는다. 같다  →  안 받는다. 그게 전부예요.

그래서 버전을 안 올리면 — 코드를 100줄 고쳤든 1000줄 고쳤든 쪽지의 숫자가 그대로라 앱은 "내 거랑 같네" 하고 무시해요.
함정

이 셋만 조심하면 돼요

실제로 만들면서 다 한 번씩 걸렸던 것들이에요.

🔢

버전 안 올리기

제일 흔해요. npm version patch 를 빼먹으면 빌드도 되고 업로드도 되는데 앱만 조용해요.

📄

파일 3개 중 누락

latest.yml 이 없으면 업데이트 자체가 안 되고, .blockmap 이 없으면 매번 108MB 전체를 받아요.

🏷️

워크플로 고친 직후

자동화 설정 자체를 바꿨다면 태그를 지웠다 다시 올려야 해요. 안 그러면 옛날 설정으로 돌아요.

파일 3개는 자동이에요. 지금 설정에선 GitHub이 알아서 셋 다 올려줍니다. 직접 손으로 올릴 때만 신경 쓰면 돼요.
안 될 때

위에서부터 하나씩 봐요

대개 1번이나 2번에서 끝나요.

1
버전을 올렸나? package.json 의 version 이 전과 다른지
npm version patch
2
태그가 GitHub에 갔나? 저장소 → Tags 에 v0.1.1 이 보이는지
git push --follow-tags
3
빌드가 성공했나? 저장소 → Actions 탭에 초록 체크가 떴는지
Actions 탭
4
Release에 파일 3개가 있나? 초안(draft)이 아니라 공개 상태인지도 같이
Releases 탭
5
앱이 확인할 때가 됐나? 6시간마다 확인해요. 급하면 앱을 껐다 켜면 바로 확인해요.
앱 재시작
외울 필요 없음

명령어 모음

평소엔 맨 위 두 줄만 쓰면 돼요.

명령언제
npm version patch
git push --follow-tags		 배포할 때 — 이게 기본. 나머지는 GitHub이 함
npm start고치면서 확인할 때 (빌드 없이 즉시)
npm run e2e배포 전 Claude 연동이 안 깨졌는지 (3~5분)
npm run dist내 PC에서 직접 굽고 싶을 때 → dist/
npm run release직접 구운 걸 손으로 올릴 때
npm run guide사용설명서를 다시 만들 때
버전 숫자 고르기 — patch 0.1.0 → 0.1.1 (버그 수정) · minor 0.2.0 (기능 추가) · major 1.0.0 (크게 바뀜). 혼자 쓰는 앱이면 거의 항상 patch 로 충분해요.
실행 결과는 전부 logs/ 폴더에 쌓여요. 명령을 쳤는데 화면에 아무것도 안 나와도 정상이에요 — 거기를 열어보면 됩니다.
